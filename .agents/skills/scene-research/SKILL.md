# 장면 후보 리서치

이 단계의 결과물은 **리서치 메모 하나**입니다. 장면 YAML은 쓰지 않습니다. YAML은 사용자가 후보를 고른 뒤, 새 세션에서 이 메모와 장면 색인만 보고 씁니다(`AGENTS.md`의 "장면 추가·정정 절차" 3번부터).

## 1. 이미 있는 것 확인 (YAML을 열지 않습니다)

- `npm run index`: 장면 목록, 주제별 장면 수. 조사할 기간이 정해져 있으면 `npm run index -- --since YYYY-MM --items`.
- `npm run index -- --grep 낱말`: 회사·모델·기관 이름으로 이미 다룬 사건과 용어집 표기를 찾습니다.
- 사이트 시작일과 기준일은 `grep -E '^(start|asOf):' content/site.yaml`로만 봅니다.
- 장면 파일은 후보가 기존 장면에 붙을지 판단할 때만, 그 파일 하나를 엽니다.

## 2. 고르는 기준

- "흐름을 바꾼 사건"만 고릅니다. 연도나 주제별 분량을 맞추려고 넣지 않습니다.
- 사이트는 ChatGPT 공개일(`site.start`, 2022-11-30)부터입니다. 그 전 사건은 상자로 만들지 않고, 필요하면 장면 `lede`의 배경으로만 씁니다.
- 중국 사건도 다룹니다. 다만 `china` 주제를 따로 만들지 않고 기존 주제에 넣습니다. 새 주제는 장면이 3개 이상일 때만 제안합니다.
- 장면 하나의 사건은 3~4개입니다. 기존 장면에 붙이자고 제안할 때는 그 장면의 사건 수(색인의 세 번째 칸)를 확인합니다. 이미 4개면 붙일 수 없으니 새 장면이나 재편을 제안합니다.

## 3. 출처

- 1차 출처(각 사 발표, 논문, 규제기관 문서, 공시, 소송 문서)를 먼저 확인합니다. 뉴스 요약은 후보를 찾는 데만 쓰고, 사실의 근거는 1차 출처로 적습니다.
- 발표일과 사건이 실제로 일어난 날을 구분합니다. 계약 체결일과 발표일, 시험일과 발표일처럼 다르면 둘 다 적습니다.
- 회사의 주장과 전망은 독립적으로 확인된 사실과 나눠 적습니다.
- 진행 중인 사건은 "보도 기준" 또는 "진행 중"이라고 적고, 민감한 사안은 양쪽 입장만 적습니다.
- 영어 이름은 `npm run index -- --grep 이름`으로 용어집을 먼저 봅니다. 없으면 공식 영문명과 그 출처를 메모에 적어 둡니다(쓰기 단계에서 `content/glossary.yaml`에 더합니다).

## 4. 웹 문서를 읽는 법 (컨텍스트 아끼기)

- 웹 문서 읽기 도구를 먼저 씁니다. 실패하거나 내용이 부실하면 `defuddle parse <URL> --md -o <파일>`로 저장한 뒤, `grep`이나 줄 범위로 필요한 부분만 읽습니다.
- 저장하는 파일은 저장소 밖 임시 폴더에 둡니다. 페이지 전문을 대화에 붙이지 않습니다.
- 같은 출처를 다시 받지 않도록, 확인한 주소와 확인한 날을 메모에 바로 적습니다.

## 5. 후보가 여럿일 때

- 하위 에이전트를 띄울 수 있으면 후보마다 하나씩 맡깁니다. 각자 아래 "후보 한 건" 양식으로 임시 폴더에 파일을 쓰고, 돌려줄 때는 세 줄(날짜, 한 문장, 반영 방식 제안)만 돌려줍니다.
- 띄울 수 없으면 후보를 하나씩 처리하되, 다음 후보로 넘어가기 전에 그 후보의 절을 파일에 씁니다.
- 마지막에 표를 쓰고, 후보 파일들은 `cat`으로 메모 뒤에 이어 붙입니다. 이어 붙일 때 다시 읽어 들이지 않습니다.

## 6. 메모 양식

파일: `docs/review/<조사한 날>-<슬러그>.md` (예: `docs/review/2026-11-03-event-research.md`). 이 폴더는 커밋되고 em dash 검사 대상입니다.

```markdown
# <기간 또는 주제> 타임라인 후보 조사

확인일: YYYY-MM-DD. 날짜 기준(발표일인지, 시간대를 바꿨는지)과 조사 범위를 한두 문장으로 적는다. 선정 순위와 장면 구성 의견은 편집 판단이며 콘텐츠에는 아직 반영하지 않았다고 밝힌다.

## 우선 검토할 후보

| 우선순위 | 날짜 | 사건 | 선정 이유 | 반영 방식 제안 |
| --- | --- | --- | --- | --- |
| 1 | MM-DD | ... | ... | 새 장면 / `<기존 id>`의 N번째 사건 / 재편 |

### 1. <사건>, <M월 D일>

- 사실 한 가지와 [1차 출처](URL).
- ...

기록할 수 있는 문장: "<장면 사건 문장에 가까운 한국어 한 문장>"

기존 장면: `<id>` (사건 N개). 겹치는 점이나 구분할 점.

영어 이름: 용어집에 없는 이름과 공식 표기 출처(있을 때만).

주의: 이 사건을 부풀려 쓰면 안 되는 지점(완료가 아님, 판정이 아님, 회사 주장임 등).
```

사건 하나에 사실은 3줄 안팎으로 씁니다. 해설은 붙이지 않습니다.

## 7. 글 규칙 (메모에도 적용)

- em dash(U+2014)를 쓰지 않습니다. 기사나 문서 제목을 옮길 때 들어 있으면 쉼표나 쌍점으로 바꿉니다. `npm test`가 `docs/` 전체를 검사합니다.
- 날짜는 절대 날짜로 씁니다. "오늘", "최근", "이번 주"처럼 읽는 날에 따라 뜻이 달라지는 말은 피합니다.
- 금지어와 "AI가 쓴 것처럼 읽히는 표현"(`AGENTS.md`의 문체 규칙)을 메모에서도 피합니다. 메모의 문장이 장면 글로 그대로 옮겨지기 쉽기 때문입니다.

## 8. 끝내기

- 메모를 쓴 뒤 `npm test -- no-em-dash`로 검사합니다.
- 사용자에게는 표의 후보와 메모 경로만 알립니다. 장면을 쓰는 일은 사용자가 후보를 고른 뒤에 합니다.
