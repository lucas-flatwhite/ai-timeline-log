# AI Timeline Log 격자 개편과 영어판 설계

- 날짜: 2026-10-25
- 바탕 문서: `docs/superpowers/specs/2026-10-18-ai-timeline-log-design.md`(이하 "10-18 문서")
- 시안: `.superpowers/brainstorm/15013-1792917035/content/`(git에 올라가지 않음, 이 컴퓨터에만 있음). 부록 A에 파일별 내용을 적었다.

이 문서에서 **(사용자)**는 사용자가 대화에서 직접 정한 것, **(제 결정)**은 설계자(Claude)가 정하고 사용자에게 알린 것이다. 표시가 없는 항목은 앞의 두 가지에서 따라 나오는 세부다.

## 1. 무엇을, 왜

지금 사이트는 한 화면에 장면 하나씩 지나가는 스크롤 연표다. 한 번 읽고 나면 다시 둘러볼 거리가 적다. 이번 개편은 첫 화면을 **판화 상자가 빽빽하게 깔린 격자**로 바꾼다. 상자 하나는 특정 날짜의 사건 하나이고, 누르면 상세가 열린다. 여러 사건을 한눈에 훑고, 끌리는 상자를 눌러 들어가는 사이트가 목표다.

같은 출시에 **영어판**을 함께 낸다(사용자). 해외 방문자도 같은 벽을 보고, 사건 단위 링크로 공유할 수 있게 한다. 외부 참여는 GitHub 이슈로 받는다(사용자).

## 2. 목표, 비목표, 반목표

**목표**
- 첫 화면이 판화 상자 격자다. 최신 사건이 맨 위다(사용자).
- 모든 상자에 판화가 보인다(사용자). 글자 상자와 그림 상자가 섞인다(사용자).
- 휴대폰에서도 빠르다. 성능이 가장 중요한 조건이다(사용자).
- 한국어·영어를 한 번에 낸다(사용자).
- 상자를 누르면 연결된 정보(같은 장면의 사건, 앞뒤 사건, 출처)를 따라갈 수 있다(사용자가 개선안을 모두 받아들임).
- 사건마다 정정·제보 링크가 GitHub 이슈로 이어진다(사용자).

**비목표**
- 장면을 넘나드는 연결(흐름, 스레드)(사용자).
- 투표, 제보 양식, 계정 같은 참여 기능(사용자: 이슈 링크로 대신).
- 10월 이후 새 사건 추가. 내용 갱신이라 개편과 따로 한다(제 결정). 시안에 넣은 2026-10-05 위키미디어 사건도 이번 출시에 넣지 않는다.
- 영어 외 언어, 사건별 OG 이미지, 방문 분석(10-18 문서 14절 그대로).

**반목표** (돌아가더라도 실패로 보는 것)
- 첫 화면이 느리다. 특히 휴대폰에서 판화가 늦게 뜬다.
- 판화 없이 글자만 있는 상자가 생긴다.
- 지금 퍼져 있는 장면 링크(`#2025-01-deepseek` 등)가 깨진다(제 결정).
- 영어판의 벽이 한국어판과 배치나 그림이 달라진다(제 결정).

## 3. 10-18 문서와의 관계

**그대로 유효한 것**: 2절의 결정 중 운영 방식, 장면 주소, 언어·언어 주소, 빌드, 배포, 작품 이름, 폰트, 라이선스, 분석 도구 / 3절 저장소 구조(아래 9절의 변경 제외) / 4절 데이터 모델(아래 6절의 추가 포함) / 5절 중 일수, 장면 수, 최근 추가, 갱신 기록 / 6절의 정적 HTML, JS는 DOM을 읽음, 엔진의 텍스트 비의존, 언어별 서체 토큰, 폰트 대기, 시드 고정 원칙 / 7절 날짜 저장 형식 / 9절 빌드 검사(아래 10절의 추가 포함) / 10절 메타·공유 / 11절 정책과 문서.

"유효하다"는 설계로서 유효하다는 뜻이지 구현됐다는 뜻이 아니다. 지금 코드에는 1단계와 2단계 일부만 들어 있다. 아직 없는 것은 다음과 같다.
- `id` 해시 시드(`view.ts`는 아직 순번 시드)
- 최근 추가·정정·갱신 기록 계산과 표시
- 금지어·상대 시간·출처 필수 검사
- `.github/`, `content/LICENSE`, `docs/editorial.md`, `CLAUDE.md`, `glossary.yaml`
- hreflang·canonical·OG 메타

이 중 무엇을 이번에 넣는지는 15절에 적는다.

**이 문서로 바뀌는 것**: 2절의 스크롤 순서, 판 번호, 최근 추가 표시 방식, 내비게이션 / 6절의 고정·먹 입히기·지우기, 밀도·풀림 판정, 지연 생성/해제 큐 / 8절 화면 전체 / 12절 중 고정·눈금자·목차 시트 테스트 / 13절 단계 중 3단계(내비게이션)는 없어지고, 4단계(영어)와 5단계(공유와 배포)의 필요한 부분이 이번 작업에 들어온다.

## 4. 화면

시안: `cover-bb.html`(표지), `grid-v9.html`(격자와 상세). 색, 서체, 판화 엔진은 지금 사이트 그대로다.

### 4.1 맨 위 막대

- 왼쪽: `AI Timeline Log`. 오른쪽: `KO EN`(현재 언어에 밑줄), `제보·정정 ↗`(en: `Report ↗`). 기간 표기(`2022.11.30 → 현재`)는 넣지 않는다(사용자).
- `제보·정정`은 저장소 이슈 목록 `https://github.com/lucas-flatwhite/ai-timeline-log/issues`로 간다. 새 창.
- 화면을 내려도 위에 붙어 있다(제 결정). 높이는 한 줄, 데스크톱 약 40px.

### 4.2 표지 상자

- 격자의 첫 상자, 4칸×3칸(사용자: B-b 안에 위 막대를 더한 형태).
- 위 4칸×2칸: 오늘까지의 일수 판화. 지금 표지처럼 먹 바탕에 밝은 글자와 햇살 문양(`rays`). 글자는 `site.yaml`의 `heroGlyph.wide`(`{days}일`, en `{days} days`).
- 아래 4칸×1칸: 소개 문장(`site.yaml`의 `lede`)만. 이름과 기간은 넣지 않는다(사용자).
- 누를 수 없다. 일수는 10-18 문서 5절대로 보는 날 기준으로 다시 채운다.
- 지금의 전체 화면 표지(`Hero`), 햇살 캔버스, `아래로` 신호는 없앤다.

### 4.3 격자

- 칸 64px, 간격 4px. 화면 폭에 맞춰 칸 수가 정해지고(`repeat(auto-fill, 64px)`), 가운데 정렬. 390px 휴대폰에서 5칸, 320px에서 4칸.
- 상자 크기: 표지 4×3, 연도 판 2×2, 장면 2×2, 사건 1×1.
- 빈자리 채우기: CSS `grid-auto-flow: row dense`. 큰 상자가 남긴 구멍을 뒤의 작은 상자가 채우므로 엄격한 날짜순은 국소적으로 한두 칸 어긋난다. 이를 받아들인다(제 결정).
- 순서(최신이 위) (사용자). 정렬 열쇠는 다음과 같다(제 결정).
  - 연도 판: 그해의 맨 앞(`YYYY-99-99`로 취급)
  - 장면 상자: 장면의 대표 날짜 `date`
  - 사건 상자: 사건 날짜. 월까지만 있는 날짜(`2023-01`)는 그달의 맨 끝(가장 오래된 쪽)
  - 같은 날짜면 장면이 사건보다 앞, 그다음 장면 `order`, 그다음 파일 순서
- 연도 판은 장면이 있는 모든 연도에 둔다. 시작 연도(2022)는 요약이 없으므로 누를 수 없는 판으로 둔다(제 결정, 시안과 같음).
- 마우스를 올리거나 키보드로 초점이 가면(제 결정)
  - 상자 왼쪽 아래에 날짜(`YYYYMMDD`)가 뜬다.
  - 같은 장면의 상자(장면 상자 포함)만 진하게 테두리가 생기고, 나머지 상자 판화는 흐려진다(불투명도 약 25%).
- 터치 기기에서는 올림 효과 없이 누르면 바로 상세가 열린다(제 결정).
- 상자를 순서대로 Tab으로 이동할 수 있다(DOM 순서 = 최신순).

### 4.4 상자의 판화

- 엔진은 `src/engine/` 그대로다. 크기에 맞춰 칼선 간격만 조정한다: `s = max(1.5, css/48) × dpr`(시안과 같음).
- **장면 상자**: 지금 장면 판화와 같은 설정(`print.pattern`, `angle`, `motif`, `glyph`).
- **사건 상자**: 장면의 `pattern`·`angle`을 물려받는다. 다만 동심원(`c`)은 작은 판에서 글자를 뭉개므로 가로(`h`)로 바꾸고, 문양은 `none`(제 결정, 시안에서 확인).
- **그림 상자**: 사건에 `pic`이 있으면 위 60%에 그림, 아래 37%에 핵심어를 새긴다(사용자: B 방식). 그림은 100×100 좌표의 윤곽선(SVG path)을 검게 칠한 밑그림이고, 그 뒤는 글자와 같은 칼선이다. 그림은 붙이기 쉬운 주제에만 쓴다(사용자). 위키피디아 같은 로고를 그대로 그리지 않고 일반적인 형태로 암시한다(제 결정).
- **연도 판**: 지금 연도 판처럼 먹 바탕, 사선 ±22°.
- 상자는 크기가 고정이라 판화가 늦게 떠도 화면이 밀리지 않는다. 새기기 전에는 나무색(`#D3D0C6`) 바탕이다.
- 시드: 장면은 `id`의 해시, 사건은 `사건 주소`(4.5절)의 해시. 장면을 끼워 넣어도 다른 판화 모양이 바뀌지 않는다(10-18 문서 6절 원칙).

### 4.5 상세

- `<dialog>`로 연다(포커스 가두기, Esc 닫기). 닫으면 누른 상자로 초점이 돌아간다.
- 데스크톱: 가운데 카드, 왼쪽 280px 판화 + 오른쪽 글. 720px 이하: 화면 전체를 덮고 판화가 위, 글이 아래(제 결정).
- 판화는 열 때 그 자리에서 280px로 새긴다(ms 단위).
- 내용(장면·사건 상자):
  - 날짜 줄: `YYYYMMDD · 분류(kicker)`. 사건 상자면 `· ‘장면 제목’ 장면의 사건`을 덧붙인다(en 문구는 builder가 en.ts에). 최근 추가 장면이면 `추가 YYYY.MM.DD`(10-18 문서 8.1).
  - 장면 제목, 장면 설명(`lede`)
  - 같은 장면의 사건 목록(`YYYYMMDD 문장`). 누른 사건은 먹 바탕으로 강조. 목록의 사건을 누르면 그 사건의 상세로 바뀐다.
  - 정정 메모(있을 때, 10-18 문서 8.1)
  - 출처: 사건 출처가 있으면 그것, 없으면 장면 출처. 없으면 줄을 숨긴다.
  - `이 사건 정정·제보 ↗`(en `Report a correction ↗`): 11절의 이슈 양식을 사건 정보가 채워진 채로 연다.
  - `← 이전 사건` `다음 사건 →`. ← → 키도 같다. 순서는 격자의 시간순(연도 판 제외, 장면 상자 포함). 왼쪽이 과거.
- 내용(연도 판): 연도, 연도 요약 제목과 본문. 목록·이동 없음.
- 주소(제 결정):
  - 장면은 `#<장면 id>`(지금과 같음), 사건은 `#<장면 id>~<YYYYMMDD>`. 같은 장면에 같은 날짜 사건이 둘이면 두 번째부터 `-2`, `-3`.
  - 상세를 열면 `history.replaceState`로 주소를 바꾸고, 닫으면 지운다. 방문 기록은 쌓지 않는다.
  - 이 주소로 들어오면 그 상세가 열린 채 시작한다. 장면의 `aliases`도 받는다. 잘못된 주소는 무시한다.

### 4.6 맺음

지금 구조 그대로다(사용자). `N일 동안 바뀐 것`과 시대 구분, `주요 모델 판본`, `출처와 기준`, 끝줄, `KO EN`이 격자 아래에 온다. 끝에 "만든 방법"(10-18 문서 11절)이 아직 없다면 이번에 넣는다. AI 도움으로 조사·작성했다는 사실, 출처 원칙, 이슈 링크를 담는다(제 결정).

### 4.7 JS가 꺼졌을 때

10-18 문서 6절 원칙(모든 글은 정적 HTML)을 지킨다(제 결정).
- 상자는 `<a href="#주소">`이고, 안에 상자 핵심어가 글자로 들어 있다. 그래서 판화가 없어도 무엇인지 보인다.
- 모든 장면의 상세 내용(제목, 설명, 사건 목록, 출처)은 HTML에 `<article id="장면 id">`로 들어 있다.
  - JS가 있으면 숨겨 두고 상세 창이 이 내용을 쓴다.
  - JS가 없으면 격자 아래에 목록으로 보이고, 상자 링크가 해당 글로 이동한다.

## 5. 성능

측정으로 정한 방식이다(사용자 승인, 부록 B).

- 판화는 브라우저가 새긴다. 단, 화면 가까이 온 상자만 새긴다(`IntersectionObserver`, 위아래 여유 약 300px). 한 프레임에 8ms 안쪽으로 나눠 새기고, 지금 보이는 상자를 먼저 새긴다.
- **판 글꼴**: 빌드할 때 언어별로 그 언어의 판에 쓰이는 글자만 담은 Black Han Sans woff2를 만든다. 포함하는 글자는 장면·사건 핵심어, 일수 판(숫자, 쉼표, `일`/`days`), 연도 숫자다. 시안 기준 한국어 173자에 24KB이고, 영어는 10KB를 넘지 않을 것으로 본다.
  - 이 글꼴은 판화 전용 글꼴 이름(예: `Plate`)으로 선언하고 `<link rel="preload">`한다.
  - 판화는 이 글꼴만 기다린다.
- 본문 글꼴(Hahmlet, IBM Plex Mono)과 상세 제목용 Black Han Sans는 지금처럼 fontsource의 글자 범위 조각으로 받는다. 격자가 뜨는 데는 필요 없다.
- 전체 화면 표지 캔버스가 없어져 첫 화면 부담이 줄어든다.
- 목표(제 결정, 시안 측정값 기준): 느린 휴대폰 흉내(CPU 4배 느리게, 지연 150ms, 1.6Mbps, HTTP/2)에서 첫 화면 상자가 모두 새겨질 때까지
  - 390px: 1.5초 이하(시안 1.38초)
  - 1440px: 2.0초 이하(시안 1.94초)
- 판화 이미지를 미리 찍어 두는 방식은 쓰지 않는다. 측정에서 더 느렸다(부록 B).

## 6. 데이터 모델 변경

10-18 문서 4절에 아래를 더한다.

```yaml
# content/scenes/2026-07-21-sandbox-escape.yaml (일부)
print:
  glyph: 탈출                 # 장면 핵심어(공용). 언어별로 다르면 en.glyph
items:
  - date: 2026-07-21
    ko: OpenAI, 평가 중 에이전트가 허깅페이스 데이터 처리 시스템에 침입했다고 공개.
    en: OpenAI discloses that an agent under evaluation broke into Hugging Face's data-processing systems.
    glyph: { ko: 침입, en: BREACH }   # 사건 핵심어. 두 언어가 같으면 문자열 하나("GPT-6")
    pic: puzzle                    # 선택. content/pics.yaml의 이름
    sources:                       # 선택. 사건 출처
      - { url: "https://...", title: "...", publisher: "..." }
en:
  kicker: Incident
  title: The Agent That Left the Sandbox
  lede: ...
  glyph: ESCAPE
```

- `items[].glyph`: 필수. 문자열 또는 `{ ko, en }`. 상자에 새길 핵심어다. 줄바꿈 `\n` 허용.
- `items[].pic`: 선택. 있으면 그림 상자(4.4절)다.
- `items[].sources`: 선택. 장면 `sources`와 같은 형식.
- `content/pics.yaml`(새 파일): `{ <이름>: { d: "<SVG path, 100×100 좌표>", cx, cy, note } }`. `cx, cy`는 그림을 상자 가운데에 놓을 기준점, `note`는 무엇을 뜻하는지 한 줄.
- 항목 수 3~4개 규칙은 이번에는 그대로 둔다(제 결정). 원래 근거(고정 스크롤 길이)는 사라졌지만, 이번 출시에 새 사건을 넣지 않으므로 바꿀 필요가 없다. 바꿀지는 다음 내용 갱신 때 정한다.

## 7. 다국어

- 주소: `/` 한국어, `/en/` 영어. 자동 리다이렉트 없음. `KO EN` 전환은 같은 사건 주소(`#...`)를 유지한 채 다른 언어로 간다(제 결정). `hreflang` 등은 10-18 문서 10절.
- 두 언어의 벽은 상자 집합, 크기, 순서, 그림, 판화 설정이 같다. 바뀌는 것은 글자뿐이다(제 결정).
- 핵심어 해석: 사건은 `glyph.<언어>` 또는 문자열 `glyph`. 장면은 `<언어>.glyph` 또는 `print.glyph`.
- 날짜 표시: 상자 날짜와 상세의 날짜는 두 언어 모두 `YYYYMMDD`로 쓴다(제 결정). 사용자가 처음 상자를 "yyyymmdd 날짜의 사건"으로 떠올렸고, 언어와 상관없이 읽힌다. 맺음의 시대·모델 날짜는 10-18 문서 7절의 언어별 형식을 따른다.
- 영어 글과 그림은 Claude가 맡는다(사용자). 범위는 12절.
- UI 문구는 `src/i18n/en.ts`에 둔다. `ko.ts`의 스크롤 연표 전용 문구(판 번호, 눈금자, `아래로` 등)는 지운다.
